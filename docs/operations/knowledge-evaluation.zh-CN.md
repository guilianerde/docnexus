# 知识维护评估

在仓库安装开发依赖后运行：

```bash
npm run eval:knowledge
```

该命令构建代码，在临时工作区回放提炼、封存、入库、分类调整和知识更新，输出 JSON 报告；检查失败时以非零状态退出，结束时删除自己的临时数据。它不初始化开发仓库的知识库、不改原始文档、不访问外部模型或网络。需要保存纯 JSON 时使用 `npm run build` 后的 `node scripts/eval-knowledge.mjs > knowledge-report.json`。

## 输入与可重复性

输入记录在仓库的 `test/fixtures/knowledge-eval.json`，来自五份真实项目文档：总体架构、文档查询契约、中文 README、发布清单、检索评估。每份保存需要在源文档中找到的证据片段，以及宿主模型在本次开发中整理的正文、主分类、分类依据与事实定义。脚本运行时读取最新原文作为入库 source，校验证据片段仍存在，并在报告中记录完整源文件 SHA-256。证据变化会要求重新阅读并更新样例。

这是已审阅决策的程序回放。分类名称属于样例，不是生产分类枚举或命名标准。事实的有效日期是评估时间基准，不是原文宣称的决策发生时间。每页 20→10 的决定、后续发布说明和另一条新知识均为明确标注的模拟输入，只影响临时项目，不会改变真实 CLI 默认值或真实项目约定。

## 程序检查

- 五份真实来源材料经过草稿封存与正式入库，分类带有依据，同主题文档复用分类；全量与逐页结果一致。
- 重新分类只改分类及审计信息，保留正文、事实和原始来源；分类拆分后无文档使用的旧类消失，旧分页版本被拒绝。
- 同一事实只定义一次；明确替代后，所属页和引用页显示新值，引用仍指向规范所属文档；旧事实保留为 superseded，另一项有效事实保留。
- 引用页的来源、metadata 和时间线保持不变；检索的当前摘录不把旧值作为现行断言，结果带有事实所属路径。
- 一个旧草稿封存后，新知识保存到同一路径；旧草稿入库被拒绝，读取合并后重新封存能保留两项改动及来源历史。
- 没有出现在知识库中的标识符不会产生字面证据。

程序验证能力与模型判断分别记录。报告中的 `checks` 只统计上述可执行条件；`model_quality.measured` 为 false。字面查找无结果不能证明模型会拒答；分类回放通过也不表示实时模型分类准确率为 100%。

## 宿主模型审阅

样例另附四项 `model_review_tasks`：分类组织、未决提议与当前约定的冲突、没有证据的问题、过期草稿合并。可让使用项目 skills 的宿主模型在另一个临时项目独立完成，保存其实际读取文档、工具调用、草稿、分类依据和最终回答，再按任务中的 criteria 审阅。

分类审阅允许不同但合理的命名，检查内容依据、已有分类复用和拆分必要性。冲突审阅检查是否把未决提议误写成有效替代；无答案审阅检查是否说明证据不足；草稿审阅检查是否真正合并当前知识与用户分类，而不是仅重新封存旧内容。记录通过、失败及具体证据，避免用预置答案替代一次真实模型运行。

该回归未测量主动读取率、模型分类准确率、自然语言冲突检测、回答质量或无证据时的真实拒答率，也不代表大型知识库性能。CI 在 Node.js 22/24 上运行程序回放；模型质量评估需要另行执行并保留实际记录。
