# 检索投影、命中出处与证据预算

文本仍是真源，检索数据库可重建。检索路径分为投影协调、候选融合、命中依据传递、证据选择与预算交付；RRF 参数、随包模型和 tokenizer 切块上限保持原有设置。

## 投影版本与升级

`index_state.projection_schema_version` 独立于工作区格式 6、草稿格式 3、机器协议 1、模型签名和切块签名。当前投影版本为 2，包含文档 `record_version` 和 chunk 的 JSONB `source_anchor`。

`index status` 与 `doctor` 返回 `schema_version`、`expected_schema_version` 和 `schema_status`，区分 missing、legacy、current、unsupported。检查不会升级或重建投影。已知旧投影、缺少版本标记的旧表，以及缺少当前必要字段的投影，在下一次 `index sync` 或 recall 时重建。

升级在数据库事务中只删除当前项目的六张派生表并重新建表，不使用 CASCADE 删除外部依赖；随后从已验证文本重新建立投影。表结构升级失败会回滚；逐文档投影失败仍使用原有同步重试机制。索引代次随升级更新，锁外准备的旧计划必须重新验证。正文、来源、metadata、时间线、草稿和自定义模型资产均保留；普通同步继续维护已有 HNSW，仅投影升级需要重建旧表及其索引。

遇到无法识别或更新版本的投影时返回 `index_schema_incompatible`，要求使用兼容程序；不会按旧结构读取或静默降级覆盖。关键词查找与文档阅读继续使用文本。旧版 CLI 本身无法识别新增版本标记，不能据此承诺与新版共享投影的双向兼容。

## 分类检索范围

`search`、默认混合 `recall`、`recall --mode vector` 和预算证据包均接受可选的 `--category <name>`，Node 输入对应 `category?: string`。规则与 `document query` 一致：精确、区分大小写，1–80 字符且无首尾空白/控制字符；不传表示所有分类，`uncategorized` 包含省略分类的旧文档，合法但不存在的分类返回空结果。

从同一次已校验文本快照选择分类对应的文档 ID。词法路在匹配和 limit 前筛选；向量路在 SQL 候选查询及长文挤占后的文档池补足查询内约束 ID，混合路在融合前约束两路。图谱路径的关系声明者、支持片段文档和支持关系声明者均在各自 SQL limit 前约束，邻接片段来自已选文档。分类修改后下一次读取生效，不增加持久化分类列或改变投影 schema 2。指定分类时先 materialize 合格片段，再在该范围内精确向量排序，补足文档池时按文档选最佳片段，避免 HNSW 全库近邻耗尽后分类过滤漏召回；代价是大分类范围可能比全库 ANN 更慢。不传分类继续使用原有 HNSW 检索。

分类过滤限制检索文档范围，已选文档引用的跨分类事实仍按真实定义者解析、携带来源并参与生命周期检查，避免把已有引用错误解释成缺失事实。证据包使用同一筛选结果，保持原有出处、预算和并发 revision 校验。

## 结构化命中出处

`search.results[].source_anchor`、召回片段的可选 `source_anchor`，以及 `context_groups[].matches[]` 传递命中依据。matches 保留 keyword/vector 两路各自的出处，即使代表片段来自向量路，关键词命中的事实仍参与证据优先级。

每个 anchor 包含实际来源文档 ID 与 `record_version`，并区分：

| kind | 内容 |
| --- | --- |
| document | 人工模板的 UTF-16 起止位置、模板哈希，以及该范围实际引用的事实 ID |
| fact | 所属文档、事实 ID 和同步时的状态；跨文档引用仍指向定义者 |
| metadata | 标题、路径、实体/别名、标签或摘要字段及完整命中值；不伪造正文位置 |

正文位置基于 CRLF 转 LF、去除全文首尾空白后的引用模板，结束位置为排他上界；标题上下文前缀不计入来源范围。切块记录渲染正文的实际范围，事实渲染器提供正文与模板的区间映射，因此生成事实块或重复段落不再依赖字符串首次匹配定位。CRLF、缩进、Unicode 与事实替代映射均有回归覆盖。

组装前检查文档版本、模板哈希、范围和事实身份/状态。失效出处返回 `index_outdated`，不会退回到其他同名段落继续引用。同步会刷新出处，即使片段文本和向量可复用；事实定义者只更新来源或分类时，引用者的投影也会刷新事实出处版本。旧调用者没有结构化 anchors 时仍兼容原来的文本定位回退。

## 选择、预留与扩展

证据组装保持完整 JSON 的保守 UTF-8 字节预算，分三步：

1. 先放入直接命中的原子事实，关键词直接命中的事实优先于向量代表片段附带的事实；同路内当前有效事实先于历史状态。事实不截断断言、来源或状态。
2. 为各主文档选择较小的命中窗口，每个来源范围先取最多 240 个 Unicode 字符，按剩余候选分配预算；metadata-only 回退也只先预留短正文，不能占用整页。预算不足时按候选次序保留能容纳的证据，并记录省略。
3. 在已保留命中的基础上，先补齐能容纳的主文档原子事实（当前有效事实先于其他历史状态），再按额外字节成本从小到大完成剩余预算能容纳的 window/section/page；随后按候选次序尝试长单元的部分扩展，最后装入关系和支持证据。扩展不能丢弃已保留的命中；相距很远的命中无法同时放进一段连续正文时保留离散窗口及省略标记。

保留块使用当前真源正文和事实解析结果；正文截断保持 Unicode 字符完整。返回单元不完整时 `truncated` 为 true，未交付块计入 `omitted_blocks`。极小预算不能容纳所有候选或完整事实，仍可能省略；预算连有效证据与引用都放不下时返回 `invalid_params`。选中候选的相关性与是否足以作答仍需单独评估。

验收包括旧投影重建/回滚、未知版本拒绝、重复正文定位、两路命中保留、跨文档出处刷新、长首文档不挤掉后续命中、离散命中保留，以及现有并发、恢复和向量复用回归。质量对照沿用 [检索评估](../operations/retrieval-evaluation.md)，旧基线保持不变，新增运行另存报告。
