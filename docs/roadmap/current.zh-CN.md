# DocNexus 当前状态与路线图

更新日期：2026-10-18。本页只记录当前状态与下一步；各轮测试数字、智能体验收过程和结论边界见[验收记录](../operations/validation-history.zh-CN.md)，版本变更见 [Changelog](../../CHANGELOG.md)。

## 当前定位

0.21.0 采用分层项目记忆：Markdown 当前知识、来源时间线、PGLite/Postgres＋pgvector 文档/chunk/关系投影、本地 ONNX embedding 和 skills 编排。文本为真源，数据库可重建，CLI 不调用外部 LLM。默认本地 PGLite，环境 URL 可选独立 Postgres。不迁移格式 5 及更早的工作区。

## 已实现

**写入与知识维护**

- 草稿格式 3：提取 → 封存 → 预览 → 入库 → 来源时间线；封存和入库都拒绝过期目标，旧草稿需复读合并。`draft preview` 返回完整封存正文、哈希与 `sealed_version`。
- 捕获 skill 在新建草稿前检索相似知识并判定 create/update/skip/conflict；CLI 不做语义合并。
- 模型动态分类并记录依据；调用方可用 `draft seal --category` 显式覆盖；支持仅分类更新与审计。
- 事实单点定义、正文按 ID 引用生成；实体别名、生效/到期/替代/撤回，跨文档失效触发索引更新。
- 跨页影响清单持久化（`docnexus/impacts/`）：save/list/get/set、追加状态历史、复核标记与 revision 并发保护；属于审阅建议，不是多页事务。

**检索与证据**

- 中英文、路径与代码标识符字面查找；中文连续汉字对补充分词，完整短语与覆盖度优先。
- 默认关键词/向量文档级 RRF 融合，相邻 chunks 与一跳图谱上下文；按实际 tokenizer 控制片段长度。
- window/section/page 证据包与保守预算规划，保留结构化出处、事实状态与截断说明。
- `search`、`recall` 与证据包支持精确分类过滤，过滤先于候选限额和融合。
- 增量索引同步、未变向量复用、持久 HNSW；投影 schema 版本 2，已知旧结构事务重建，未知版本拒绝。

**可靠性与工程**

- 工作区格式 6，文本随 Git 保存；可选独立知识仓库，固定单一本地分支。
- 本机项目锁、持久化文本事务、中断后的保存/删除/回滚恢复；模型与 embedding 在锁外准备、锁内校验提交。
- 机器错误协议、`--json` 失败输出、`protocol` 发现与 doctor 结构化 issues。
- 本地只读文档浏览页与全量/分页文档查询接口。
- 本地使用记录、匿名指标、显式反馈与单文件导出。
- 确定性测试、真实离线模型 E2E、安装包冒烟测试；CI 覆盖 Linux 原生 Postgres，以及 macOS / Windows 上的 PGLite 路径（Windows 首次通过前为非阻塞）。
- 固定中英文检索评估集、扩展质量基线（开发/保留集分开）与知识维护程序回放，详见[检索评估](../operations/retrieval-evaluation.md)和[知识维护评估](../operations/knowledge-evaluation.zh-CN.md)。

## 已知缺口

- 缺失时区、多页并发修订、原生宿主自动激活与全库影响覆盖尚未经独立模型实测。
- 现有智能体验收为单一临时项目内顺序多题，不能外推为准确率；skills 跳过分类的独立模型行为未单独实测。
- 尚无 100 / 1000 / 10000 文档规模的性能基准。
- Windows 上的锁、重命名与恢复行为尚无通过记录。

## 后续优化顺序

继续以本地项目记忆、文本真源、可重建检索投影和宿主 skills 编排为定位。按下列验收门槛进入下一阶段；版本号和工期在范围冻结后确定。

### 阶段 1 · P0：关闭实测缺口

| 工作 | 交付物 | 验收标准 |
| --- | --- | --- |
| 来源时间归因（本轮样例通过） | 当前来源时间规则、无日期/明确观察时间/仅事件日期任务及回归 | 新来源未知日期不沿用旧值；明确日期准确保留；历史事实 `valid_from` 与 provenance 不变。缺失时区仍待独立模型实测 |
| 独立复测（本轮已执行） | 新随机值、新临时项目、新上下文的原始运行归档及父智能体语义审阅 | 保留 41 次实际调用、最终文本和审阅依据；不重写答案或通过放宽判定掩盖失败，不外推为准确率 |
| 预览读取观测（已实现并实测） | `draft preview` 正文/哈希/封存版本，seal/入库版本关联 | 分别记录“已生成”“已交付正文”“智能体声明已审阅”；不把交付当作理解或批准 |

本阶段只收紧已观察到的行为，不增加服务端 LLM 或自动整理流程。本轮按新增授权补充了跨页影响清单及一个独立场景；仍由宿主 skills 判断，分别封存并保存相关页，不扩展为后台整理服务。

### 阶段 2 · P1：建立检索与证据质量基线

1. 建立首批不少于 30 个有依据的真实项目问题，覆盖标识符、别名、中英文改写、跨文档关系、长文末尾、事实替代、冲突及无答案问题；开发集与保留集分开。
2. 对照关键词、纯向量、混合召回，以及 window/section/page 证据交付。固定候选结果做证据组装对照，避免同时改变召回和上下文后无法归因。
3. 分别统计文档召回、证据覆盖、引用正确、拒答、主动读取、模型实际调用数和延迟；给出样本数、失败例和未验证项。原生宿主需另测重启/新会话中的实际调用，安装文件不作激活证明。
4. 检查紧预算下的事实省略、原文命中定位、重复支持证据和截断策略。具备明确目标 tokenizer 时再增加可选精确计数；未知时继续标明保守估算。embedding 输入预算与回答证据预算保持独立。

验收门槛：事实状态和出处不可因预算被伪造或错配；无证据不能因近邻结果变成有答案；现有确定性与恢复回归全过。模型指标先冻结基线再设门槛，不用当前小型样例宣布普遍提升；新策略须在保留集验证后才改变默认行为。

### 阶段 3 · P1：稳定升级、契约与恢复

| 工作 | 交付物 | 验收标准 |
| --- | --- | --- |
| 投影 schema 版本（已实现） | 独立版本 2、兼容状态诊断、已知旧结构事务重建与未知版本拒绝 | 旧标记、缺失字段和升级失败回滚有回归覆盖；从文本重建并保留来源、事实、时间线和草稿。后续结构变化继续更新投影版本 |
| 接口兼容回归 | CLI 错误、doctor、预算证据与分页的契约样例和兼容说明 | 旧成功字段含义不变；新增可选字段可忽略；未知错误码不能被误当成功或自动重试；不把改写错误文字当破坏性变更 |
| 恢复与平台矩阵 | Linux/macOS/Windows 的进程中断、锁释放、部分写入和索引故障记录 | 恢复后来源、正文、metadata、时间线和草稿收据一致；未知写入结果先检查再处理；持续记录未覆盖的平台和断电边界 |

未来若文本格式需要变化，应先给出备份、预览、迁移和失败恢复契约；派生索引升级不必复制 GBrain 的整库迁移流程。本阶段不自动恢复对格式 5 及以前工作区的支持。

### 阶段 4 · P2：以规模基准指导性能优化

先建立 100 / 1000 / 10000 文档的分级基准，并控制长文比例、片段数、事实密度和一跳关系密度。小规模稳定后再放大；存储基准与真实模型成本分别测量。

必须记录：

- CLI 冷启动、同进程模型预热、PGLite 打开/关闭及远程 Postgres 往返成本。
- 无变化召回、少量文档增量、事实到期/替代、模型变化及全量重建的 p50/p95、内存、文件读取和 embedding 调用数。
- 并发文本读取/写入的等待、冲突重试、向量候选补查和图谱上下文成本；HNSW 是否实际被采用需查执行计划。

根据结果优先评估无变化同步的快路径、数据库租约复用、SQL 批处理与重复扫描减少。若全库完整性校验是瓶颈，必须先定义缓存失效和外部编辑检测的可承诺边界，不能用 mtime 缓存悄悄削弱真源校验。

验收门槛：与冻结基线对照，报告各阶段耗时与内存变化；优化不引入旧索引作答、不漏事实时间变化、不破坏锁和文本恢复；未变化片段继续复用向量。性能目标值在首次基准后确定。

只有基准证明同步耗时确实影响使用时，才增加可恢复的批量同步游标/任务：先支持显式执行、断点续跑和失败诊断，再评估后台 worker。查询仍需明确其新鲜度，不能静默返回未同步数据。

### 阶段 5 · P3：按使用数据扩展能力

- **检索反馈**：先记录被使用的文档版本和可复现的失败样例，进入评估集。只有基线稳定后才实验有界调权；旧版本反馈不惩罚已修正文档，反馈不改变事实有效状态。
- **轻量主动上下文**：先提供少量明确实体/路径指针、会话内去重和实际使用记录。是否自动注入由命中质量和使用率决定；存在歧义时不强行提示。
- **后台同步**：以阶段 4 的等待时间和待处理规模为进入条件，不作为默认必装服务。

进入条件：前序正确性门槛通过、存在真实使用需求，并有开关和与现有路径的对照评估。远程 MCP、多用户权限、自动采集、多跳推理、外部模型供应商和自动知识整理需要单独产品范围，不在本路线图中自动展开。

## 下一轮建议范围

阶段 1 的来源归因已通过本轮复测样例，预览交付观测已落地；后续补缺失时区、多页并发与原生宿主激活样例。阶段 2 的首批语料和离线程序基线已建立，仍需真实使用问题与独立宿主模型的回答、引用、拒答和主动读取评估。可靠性中的版本契约可以随相关改动落地；队列、反馈调权和常驻服务等待测量结果。
