# DocNexus 当前状态与路线图

更新日期：2026-10-15。

## 当前定位

0.17.0 采用分层项目记忆：Markdown 当前知识、来源时间线、PGLite/Postgres＋pgvector 文档/chunk/关系投影、本地 ONNX embedding 和 skills 编排。文本为真源，数据库可重建，CLI 不调用外部 LLM。对齐 GBrain 双引擎模式，默认本地 PGLite，环境 URL 可选独立 Postgres。旧历史方案文档保持删除，不迁移格式 5 及更早的工作区。

## 已实现

- 捕获 skill 在新建草稿前检索、全文比较并交接 create/update/skip/conflict 判定；直接保存旧草稿补做检查，独立评审事件分别保留。CLI 不做语义合并，实际模型行为需独立验收。

- `search`、混合/纯向量 `recall` 和预算证据包支持精确分类过滤；候选限额、融合与图谱扩展前限制范围，未分类与重新分类兼容，跨分类事实引用保留定义者出处。

- 共享机器错误协议、--json 失败输出、protocol 发现与 doctor 结构化 issues；错误在源头分类，不按消息文字猜测。
- window/section/page 独立证据包，完整 JSON 的保守预算、来源版本与观察时间、原子事实状态及截断/省略说明。
- 独立上下文智能体验收入口：随机事实、实际 CLI 调用与后置状态记录、过期草稿复读合并检查；机械检查通过仍需语义审阅，不等同于模型质量结论。

- 本地只读文档浏览页：动态分类、分页阅读、分类依据与事实来源；手动/15 秒轮询刷新，版本变化时重新加载第一页；未变化的相同视图以 ETag/304 跳过 HTML 渲染和正文传输，保留真源与事实时间检查。
- 工作区格式 6，文本随 Git 保存；关键词查找、全文读取直接使用当前文本。
- 六个工作流 skills，主动读取目录和知识，写入需用户授权。
- 大模型结合项目与相关文档动态决定分类、复用或调整已有名称，记录判断依据；支持仅分类更新与历史审计。
- 可选调用方显式分类：`draft seal --category <name> [--category-reason <basis>]` 覆盖本次草稿分类，跳过模型分类；原样保存分类名，将依据纳入封存哈希、审阅和审计。同次分类维护保留调用方选择，后续可显式调整；仍拒绝过期目标和封存后篡改。
- 提供全量/分页当前正文查询、实际分类计数、快照 revision 和独立接口脚本，查询不触发模型或写入。
- 草稿封存、审阅、保存当前知识和来源时间线；重复提交不追加事件。
- 草稿格式 3：读取返回 record_version，更新封存必须提交提炼所依据的版本；封存与入库均拒绝过期目标，覆盖读取之后的正文、来源、分类更新，以及被占用、删除或重建的路径。旧草稿需复读合并后重新封存。
- 操作内共享已校验知识快照，固定事实时间，每份真源资产只读取一次；分页仅渲染当前页，纯知识规则独立于文件读取与入库编排。
- 轻量候选与最终上下文分离，补足被长文挤占的文档候选，在 SQL 层限制图谱证据并批量读取相邻片段。
- 投影 schema 独立版本 2：诊断旧版本与字段缺失，事务重建当前项目的已知旧派生表，拒绝未知/更新版本；来源、正文、时间线、草稿和模型资产保留。
- 两路召回贯通结构化出处：文档版本、人工模板范围、事实 ID 或 metadata 字段，保留关键词与向量各自命中；重复段落按真实范围定位，事实定义者只改来源也刷新引用者出处，未变向量继续复用。
- 预算规划先保留直接事实和各候选的短命中，再补齐主文档原子事实；按增量字节成本完成能放下的单元，最后部分扩展长文及支持上下文，防止早期长文占满预算。
- 模型加载、探针、查询与片段 embedding 在锁外准备；锁内校验文本版本、事实时间状态与索引代次后提交。并发变化有界重试，PGLite 租约及最终检索仍受锁保护。
- 中英文、路径与代码标识符字面查找；默认关键词/向量文档级 RRF 融合，相邻 chunks 与一跳图谱上下文。
- 中文连续汉字对补充分词，多词查询抑制孤立单字；完整短语与覆盖度优先排序，摘录选择最强证据并保留实际出处。
- 按实际 tokenizer 控制长文与有效事实的片段长度，包含标题/重叠/特殊 token；embedding 入口拒绝超限输入，策略签名变化自动重建旧索引。离线真实模型覆盖长段落、代码和事实末尾结论的纯向量前三召回。
- 本机项目锁、持久化文本事务、中断后的保存/删除/回滚恢复，草稿入库收据与文本一同恢复。
- 规范实体别名、事实来源与生效/到期/替代/撤回，跨文档事实失效会触发受影响索引更新。
- 事实在所属 metadata 定义一次，正文通过 ID 引用自动生成；跨文档视图联动、时间刷新、预览封存与恢复不重复追加来源历史。
- 固定中英文检索评估集与离线真实模型对照命令，详见 [检索评估](../operations/retrieval-evaluation.md)。
- 扩展仓库原文锚定的检索质量基线：30 个可回答项目问题、6 个无答案问题与 8 个明确模拟场景，按目标文档族分开开发/保留集；对照关键词、纯向量、混合召回，并固定候选比较三种证据范围和两档预算。默认及 CI 只跑开发集，首次全量结果保留失败例；程序证据保留率不作宿主回答或拒答质量结论。
- 使用五份仓库真实文档回放分类、事实替代、来源引用和过期草稿合并，提供八项宿主模型审阅任务；详见 [知识维护评估](../operations/knowledge-evaluation.zh-CN.md)。程序回放不衡量模型判断准确率。
- 增量索引同步、未变 chunks/向量复用、持久 HNSW、克隆后补建、模型输出签名变化检测；文档、chunks 和关系在同一数据库事务内提交，失败回滚并于下次同步重试。
- 图关系记录所属文档与描述，更新和删除只移除该文档的关系声明。
- 实体为空的文档也可列入目录并语义召回。
- 文本完整性诊断、派生索引状态、图谱审计修复、本地模型检查、删除与 reset。
- 确定性测试、真实离线模型 E2E、类型检查、构建与锁定依赖的安装包验证。

生产依赖审计通过 high/critical 门禁；`sprintf-js` 的传递链仍有 5 条 moderate 告警，后续单独评估 Transformers 升级，详见发布检查文档。

## 本轮实测基线

2026-10-15 完成一轮用户授权的独立新上下文验收：11 项机械检查通过，召回、更新、证据不足拒答和过期草稿合并的回答与最终文本经父智能体核对一致。四项任务顺序运行于同一个临时项目，不是四个独立试验；使用关键词搜索与全文读取，不能据此证明向量召回质量、原生宿主自动激活或总体准确率。

实测观察到的未关闭项：

- 新来源替换 `source.md` 后，metadata 仍沿用旧来源的观察日期。提炼规则已补充，但尚未完成新的独立盲测。
- 观测器曾因命令前缀说明不清而收到两次错误调用；提示与示例已澄清，生成结果及相关检查通过。
- CLI 日志能证明预览封存和入库，尚不能单独证明预览文件被打开；需要补充文件读取观测。

本轮实现后的最近一次完整回归为 262 项测试通过，类型检查与构建通过，知识维护程序回放 29 项检查通过。扩展离线检索基线包含 44 个问题与 792 次证据交付对照，初次报告和架构改动后的报告均保留；机械出处、事实状态和预算检查均无违规。架构对照中，原保留集混合召回的 section/4000 标注证据完整保留从 8/9 变为 9/9，关键词单路开发集从 18/21 变为 17/21，不能据此宣布总体质量提升。原保留题已参与诊断，后续泛化验收需新的未见样本。回归、程序证据保留与宿主模型行为分别报告；显式分类的 CLI 链路已验证，skills 跳过分类的独立模型行为尚未单独实测。

## 后续优化顺序

继续以本地项目记忆、文本真源、可重建检索投影和宿主 skills 编排为定位。按下列验收门槛进入下一阶段；版本号和工期在范围冻结后确定。

### 阶段 1 · P0：关闭实测缺口

| 工作 | 交付物 | 验收标准 |
| --- | --- | --- |
| 来源时间归因 | 覆盖旧来源有日期、新来源无日期、新来源明确给出日期的任务与回归 | 新来源未知日期不沿用旧值，不以保存时间代替；明确日期准确保留；历史事实 `valid_from` 与 provenance 不变 |
| 独立复测 | 新随机值、新临时项目、新上下文的运行记录 | 保留真实调用、最终文本及审阅结果；失败不靠重写答案或修改检查器转为通过 |
| 预览读取观测 | 能记录预览实际读取及其哈希/版本的入口 | 回执区分“已生成”“已读取”和“智能体声明已审阅”；不能把读取本身当作审阅质量证明 |

本阶段只收紧已观察到的行为，不增加服务端 LLM 或自动整理流程。完成后形成一份新的验收记录，明确时间归因是否关闭。

### 阶段 2 · P1：建立检索与证据质量基线

1. 建立首批不少于 30 个有依据的真实项目问题，覆盖标识符、别名、中英文改写、跨文档关系、长文末尾、事实替代、冲突及无答案问题；开发集与保留集分开。
2. 对照关键词、纯向量、混合召回，以及 window/section/page 证据交付。固定候选结果做证据组装对照，避免同时改变召回和上下文后无法归因。
3. 分别统计文档召回、证据覆盖、引用正确、拒答、主动读取、模型实际调用数和延迟；给出样本数、失败例和未验证项。原生宿主需另测重启/新会话中的实际调用，安装文件不作激活证明。
4. 检查紧预算下的事实省略、原文命中定位、重复支持证据和截断策略。具备明确目标 tokenizer 时再增加可选精确计数；未知时继续标明保守估算。embedding 输入预算与回答证据预算保持独立。

验收门槛：事实状态和出处不可因预算被伪造或错配；无证据不能因近邻结果变成有答案；现有确定性与恢复回归全过。模型指标先冻结基线再设门槛，不用当前小型样例宣布普遍提升；新策略须在保留集验证后才改变默认行为。

### 阶段 3 · P1：稳定升级、契约与恢复

| 工作 | 交付物 | 验收标准 |
| --- | --- | --- |
| 投影 schema 版本（已实现） | 独立版本 2、兼容状态诊断、已知旧结构事务重建与未知版本拒绝 | 旧标记、缺失字段和升级失败回滚有回归覆盖；从文本重建并保留来源、事实、时间线和草稿。后续结构变化继续更新投影版本 |
| 接口兼容回归 | CLI 错误、doctor、预算证据与分页的契约样例和兼容说明 | 旧成功字段含义不变；新增可选字段可忽略；未知错误码不能被误当成功或自动重试；不把改写错误文字当破坏性变更 |
| 恢复与平台矩阵 | Linux/macOS/Windows 的进程中断、锁释放、部分写入和索引故障记录 | 恢复后来源、正文、metadata、时间线和草稿收据一致；未知写入结果先检查再处理；持续记录未覆盖的平台和断电边界 |

未来若文本格式需要变化，应先给出备份、预览、迁移和失败恢复契约；派生索引升级不必复制 GBrain 的整库迁移流程。本阶段不自动恢复对格式 5 及以前工作区的支持。

### 阶段 4 · P2：以规模基准指导性能优化

先建立 100 / 1000 / 10000 文档的分级基准，并控制长文比例、片段数、事实密度和一跳关系密度。小规模稳定后再放大；存储基准与真实模型成本分别测量。

必须记录：

- CLI 冷启动、同进程模型预热、PGLite 打开/关闭及远程 Postgres 往返成本。
- 无变化召回、少量文档增量、事实到期/替代、模型变化及全量重建的 p50/p95、内存、文件读取和 embedding 调用数。
- 并发文本读取/写入的等待、冲突重试、向量候选补查和图谱上下文成本；HNSW 是否实际被采用需查执行计划。

根据结果优先评估无变化同步的快路径、数据库租约复用、SQL 批处理与重复扫描减少。若全库完整性校验是瓶颈，必须先定义缓存失效和外部编辑检测的可承诺边界，不能用 mtime 缓存悄悄削弱真源校验。

验收门槛：与冻结基线对照，报告各阶段耗时与内存变化；优化不引入旧索引作答、不漏事实时间变化、不破坏锁和文本恢复；未变化片段继续复用向量。性能目标值在首次基准后确定。

只有基准证明同步耗时确实影响使用时，才增加可恢复的批量同步游标/任务：先支持显式执行、断点续跑和失败诊断，再评估后台 worker。查询仍需明确其新鲜度，不能静默返回未同步数据。

### 阶段 5 · P3：按使用数据扩展能力

- **检索反馈**：先记录被使用的文档版本和可复现的失败样例，进入评估集。只有基线稳定后才实验有界调权；旧版本反馈不惩罚已修正文档，反馈不改变事实有效状态。
- **轻量主动上下文**：先提供少量明确实体/路径指针、会话内去重和实际使用记录。是否自动注入由命中质量和使用率决定；存在歧义时不强行提示。
- **后台同步**：以阶段 4 的等待时间和待处理规模为进入条件，不作为默认必装服务。

进入条件：前序正确性门槛通过、存在真实使用需求，并有开关和与现有路径的对照评估。远程 MCP、多用户权限、自动采集、多跳推理、外部模型供应商和自动知识整理需要单独产品范围，不在本路线图中自动展开。

## 下一轮建议范围

阶段 2 的首批语料和离线程序基线已建立，见检索评估的来源型质量基线。阶段 1 的来源归因与预览读取观测仍需关闭；阶段 2 后续需要真实使用问题与独立宿主模型的回答、引用、拒答和主动读取评估。可靠性中的版本契约可以随相关改动落地；队列、反馈调权和常驻服务等待测量结果。
